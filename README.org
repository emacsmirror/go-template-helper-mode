#+title: go-template-helper-mode
#+options: toc:t

=go-template-helper-mode= adds Go =text/template= highlighting to another
Emacs major mode.  It is intended for Helm charts, YAML manifests, HTML, and
other files where the surrounding language should keep control of indentation,
comments, navigation, and syntax.

#+begin_src text
  message: "prefix {{if .Values.enabled}}active{{else}}inactive{{end}} suffix"
#+end_src

Version 2.0.0 is recommended for new and existing users.  It highlights only
complete actions, preserves host-language faces, and uses the shared scanner
from =go-template-mode=.

* Choose the right mode

| Buffer contents                     | Recommended setup                           |
|-------------------------------------+---------------------------------------------|
| Helm or YAML templates              | A YAML mode with =go-template-helper-mode= |
| HTML containing template actions    | =html-mode= with the helper                 |
| Primarily Go template or plain text | =go-template-mode=                         |

Use =go-template-mode= directly when no surrounding language needs to remain
active.

* Features

- Highlights complete Go template actions, comments, strings, variables,
  fields, action words, constants, and standard predefined functions.
- Preserves the host mode's syntax table, indentation, comments, keymap, and
  Font Lock defaults.
- Gives template faces precedence only inside complete actions.
- Restores host-language faces when the helper is disabled.
- Uses JIT Lock for incremental, demand-driven fontification.

* Requirements

- Emacs 28.1 or later.
- =go-template-mode= 2.0.0 or later.
- A host major mode appropriate for the surrounding language.

Built-in =html-mode= requires no additional package.  YAML examples use the
third-party =yaml-mode= package, but =yaml-mode= is not a runtime dependency of
the helper.  The automated suite covers =html-mode=; a separate manual
integration check used =yaml-mode= 0.0.16.

* Upgrading from 1.x

Version 2.0.0 removes the helper's separate regular expressions and vocabulary
and delegates fontification to =go-template-mode=.

Existing MELPA users must upgrade =go-template-mode= first and then upgrade
=go-template-helper-mode=.  This explicit order matters for rolling MELPA
installations because an older date-based package version may appear newer than
the semantic dependency version.

Other visible changes include:

- Ordinary host text such as =if=, =printf=, or =$value= no longer receives
  template faces outside complete actions.
- Actions inside quoted HTML and YAML values override the host string face.
- Disabling the helper restores host-language faces.

See [[file:NEWS][NEWS]] for the complete user-visible changes.

* Installation

** MELPA

Install =go-template-helper-mode= from MELPA or MELPA Stable.  Once version
2.0.0 is available there, new installations receive =go-template-mode=
automatically as a package dependency.

At the time of this README update, both archives still exposed the previous
implementations while publication of 2.0.0 was pending.  Check that both archive
entries have refreshed before installing.  Until then, use the manual
installation instructions with the 2.0.0 source trees for
[[https://codeberg.org/rch/go-template-mode/src/tag/2.0.0][go-template-mode]] and
[[https://codeberg.org/rch/go-template-helper-mode/src/tag/2.0.0][the helper]].

For YAML and HTML buffers:

#+begin_src elisp
  (use-package yaml-mode
    :ensure t)

  (use-package go-template-helper-mode
    :ensure t
    :hook ((yaml-mode . go-template-helper-mode)
           (html-mode . go-template-helper-mode)))
#+end_src

Omit the =yaml-mode= declaration and hook when only built-in =html-mode= is
needed.

** Manual

Place both package directories on =load-path=, then load the helper:

#+begin_src elisp
  (add-to-list 'load-path "/path/to/go-template-mode")
  (add-to-list 'load-path "/path/to/go-template-helper-mode")
  (require 'go-template-helper-mode)
#+end_src

* Usage

Enable or disable the helper in the current buffer with
=M-x go-template-helper-mode=.  To enable it whenever a host mode starts:

#+begin_src elisp
  (add-hook 'html-mode-hook #'go-template-helper-mode)
  (add-hook 'yaml-mode-hook #'go-template-helper-mode)
#+end_src

** Limit the helper to Helm templates

Use a conditional hook when ordinary YAML files should not contain template
highlighting:

#+begin_src elisp
  (defun my-go-template-helper-maybe-enable ()
    "Enable template highlighting in Helm YAML templates."
    (when (and buffer-file-name
               (string-match-p
                (rx "/templates/" (* any) "." (or "yaml" "yml") eos)
                buffer-file-name))
      (go-template-helper-mode 1)))

  (add-hook 'yaml-mode-hook #'my-go-template-helper-maybe-enable)
#+end_src

** File association precedence

The =go-template-mode= package associates =.gotmpl=, =.tpl=, and =.tmpl= with
its major mode.  Since =auto-mode-alist= uses its first matching entry, add a
host-mode association after package activation when the host should take
precedence:

#+begin_src elisp
  (add-to-list 'auto-mode-alist '("\\.tpl\\'" . yaml-mode))
#+end_src

* Behavior

Loading the helper loads =go-template-mode-font-lock=, not the
=go-template-mode= major-mode feature.  Enabling the helper installs shared
Font Lock rules in the current buffer; disabling it removes those rules and
refontifies the host buffer.

Only complete ={{ ... }}= actions receive template faces.  Host faces remain
outside actions, including the surrounding portions of quoted HTML attributes
and YAML values.

* Limitations

- The helper changes fontification only.  It does not add indentation,
  navigation, completion, or validation.
- Only the default ={{= and =}}= delimiters are supported.
- Helm, Sprig, and application-defined functions are not recognized as Go's
  standard predefined functions.
- Tree-sitter host modes have no dedicated integration and are not part of the
  verified host set.
- Unterminated or structurally incomplete actions are left to the host mode.

* Development

The default build expects a sibling checkout of =go-template-mode=:

#+begin_src sh
  make clean all
#+end_src

Override the dependency location when necessary:

#+begin_src sh
  make clean all GO_TEMPLATE_MODE_DIR=/path/to/go-template-mode
#+end_src

Run the tests or remove generated byte-code files separately:

#+begin_src sh
  make test
  make clean
#+end_src

** Manual font-lock check

The committed
[[file:tests/font-lock-manual.yaml][YAML/Helm visual regression fixture]]
contains host text, quoted and commented actions, standard and Helm-specific
functions, and intentionally malformed input.  It is for visual inspection,
not template execution.

Open it in a configured Emacs, ensure =yaml-mode= is active, and run
=M-x go-template-helper-mode=:

#+begin_src sh
  emacs tests/font-lock-manual.yaml
#+end_src

For an isolated check with a =yaml-mode= checkout or package directory:

#+begin_src sh
  emacs -Q -L /path/to/yaml-mode -L ../go-template-mode -L . \
    -l yaml-mode.el -l go-template-helper-mode.el \
    --eval '(progn
      (find-file "tests/font-lock-manual.yaml")
      (yaml-mode)
      (go-template-helper-mode 1))'
#+end_src

Template faces should replace YAML string or comment faces only inside complete
actions.  Disable the helper to confirm that the original YAML faces return.
