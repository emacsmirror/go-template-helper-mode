#+title: go-template-helper-mode
#+options: toc:t

=go-template-helper-mode= adds Go =text/template= highlighting to another
major mode without replacing that mode's editing behavior.  It is intended for
Helm charts, YAML manifests, HTML, and other files that embed complete
={{ ... }}= actions.

* Features

- Highlights complete Go template actions, comments, strings, variables,
  fields, action words, constants, and predefined functions.
- Preserves the host mode's syntax table, indentation, comments, keymap, and
  Font Lock defaults.
- Restores host-language faces when the helper is disabled.
- Uses Emacs JIT Lock for incremental fontification.

* Requirements

- Emacs 28.1 or later
- =go-template-mode= 2.0.0 or later

The helper uses =go-template-mode-font-lock= from the owner package.  It does
not maintain a separate scanner or template vocabulary.

* Installation

** MELPA

The =go-template-mode= dependency is installed automatically:

#+begin_src elisp
  (use-package go-template-helper-mode
    :ensure t
    :hook (yaml-mode . go-template-helper-mode))
#+end_src

** Manual

Place both package directories on =load-path=, then load the helper:

#+begin_src elisp
  (add-to-list 'load-path "/path/to/go-template-mode")
  (add-to-list 'load-path "/path/to/go-template-helper-mode")
  (require 'go-template-helper-mode)
#+end_src

* Usage

Enable the mode in any host buffer that contains Go template actions:

#+begin_src elisp
  (add-hook 'html-mode-hook #'go-template-helper-mode)
  (add-hook 'yaml-mode-hook #'go-template-helper-mode)
#+end_src

To limit it to Helm chart templates:

#+begin_src elisp
  (defun my-go-template-helper-maybe-enable ()
    "Enable template highlighting in Helm YAML templates."
    (when (and buffer-file-name
               (string-match-p
                (rx "/templates/" (* any) "." (or "yaml" "yml") eos)
                buffer-file-name))
      (go-template-helper-mode 1)))

  (add-hook 'yaml-mode-hook #'my-go-template-helper-maybe-enable)
#+end_src

The owner package associates =.gotmpl=, =.tpl=, and =.tmpl= with
=go-template-mode=.  =auto-mode-alist= uses its first matching entry.  Add a
host-mode association after package activation when one of those extensions
should remain YAML or another host language:

#+begin_src elisp
  (add-to-list 'auto-mode-alist '("\\.tpl\\'" . yaml-mode))
#+end_src

* Behavior

Loading the helper loads the shared fontification library, not the owner major
mode.  Enabling the helper installs the shared Font Lock rules in the current
buffer; disabling it removes those rules and refontifies the host buffer.

Only complete actions are highlighted.  Ordinary host text such as =if=,
=printf=, or =$value= is left to the host mode.  Template faces take precedence
inside an action, including actions embedded in quoted HTML or YAML values.

The helper changes fontification only.  It does not add template indentation,
navigation, completion, validation, Helm/Sprig vocabulary, custom delimiters,
or tree-sitter integration.

* Development

The default build expects a sibling checkout of =go-template-mode=:

#+begin_src sh
  make clean all
#+end_src

Override its location when necessary:

#+begin_src sh
  make clean all GO_TEMPLATE_MODE_DIR=/path/to/go-template-mode
#+end_src

** Manual font-lock check

The repository
[[file:tests/font-lock-manual.yaml][YAML/Helm visual regression fixture]]
contains representative host text, quoted actions, template comments, standard
and Helm-specific functions, and intentionally malformed input.  It is for
visual inspection, not template execution.

Open it in a normally configured Emacs, ensure =yaml-mode= is active, and run
=M-x go-template-helper-mode=:

#+begin_src sh
  emacs tests/font-lock-manual.yaml
#+end_src

For an isolated check with a =yaml-mode= checkout or package directory:

#+begin_src sh
  emacs -Q -L /path/to/yaml-mode -L ../go-template-mode -L . \
    -l yaml-mode.el -l go-template-helper-mode.el \
    --eval '(progn
      (find-file "tests/font-lock-manual.yaml")
      (yaml-mode)
      (go-template-helper-mode 1))'
#+end_src

Template faces should replace YAML string or comment faces only inside complete
actions.  Disable the helper to confirm that the original YAML faces return.
